# Changelog

Newest first. `STATUS.md` maps the implementation onto `DESIGN.md` and names
the test behind each behaviour; this file is the short version for someone
deciding whether to upgrade. Installers live on the GitHub release page for
each tag, whose notes are generated by `.github/workflows/release.yml`.

## Unreleased — 0.1.1-rc2

### Fixed

- **`ff stats` no longer freezes while the daemon crawls.** The command took the
  index read lock unconditionally, so a crawl holding the writer left it silent
  until `^C` — the whole `crawl_dir` item had to finish, not just one insert.
  Both reads are now bounded at 50 ms and the answer is honest about what it
  could not see: `partial` plus `partial_reason`, entry counts omitted rather
  than reused from a stale tick, and the per-root list omitted (never an empty
  one, which would read as "no roots configured") when that table is busy. The
  client already knew how to render `partial` as a warning; nothing had sent it.

### Added

- **Created-age fields take `HH:MM` and ages** (`3 days ago`) beside
  `YYYY-MM-DD`, with a dropdown next to each field. A bare clock time means the
  most recent occurrence of it, widened to a 24-hour window ending there when no
  date accompanies it; months and years are calendar arithmetic, so one month
  before 31 March is 28 February, not 3 March. The dropdown only writes text
  into the field it sits beside, so the field stays the single source of truth.
  Its rows run from 1, 5, 10 and 30 minutes ago up to a year, in increasing
  reach, with `any time` last as the empty window.

### Verified

- **The format-3 → current created-time migration is exercised end to end**
  (`crates/fflocate/tests/created_migration.rs`): a dated v3 snapshot migrates
  in place and keeps every minute — including minute 0, which v3 could not
  express and which must never come back as 1970 — a second pass changes
  nothing, and a bound at 60 s correctly excludes minute 0 while keeping a
  migrated minute-1 row. The stored minute also pays for itself: a
  `since`-bounded query over 20 000 rows runs in ~2.3 ms where statting each
  candidate for its birth time costs ~21 ms.
- **The AppKit build compiles and its foldout band is clickable on macOS.** A
  stale `Send` bound on `Button::on_click` rejected the distance row's `-`/`+`
  closures, which had kept the macOS job from reaching any of its tests, and
  `Expander::header_handle` now addresses the band. The headless foldout test
  skips instead of letting GTK exit the process on a runner with no display.

## 0.1.1-rc1 — 2026-11-23

### Fixed

- **Nested roots no longer index the same file once per root.** With `/`,
  `/home` and `/home/john` configured, the crawl only treated mountpoints as
  boundaries, so each walk descended into the next: three identical hits and
  nine entries for a tree that needs one hit and six. Another root's absolute
  path is now a crawl boundary, matched on the path rather than the id (the
  entry reached from `/` is not the root's own root-dir entry); a directory
  that *is* a root is still descended. Stores crawled before this keep their
  duplicates until the parent root is rescanned.
- **The index has a per-parent child index,** so `lookup` and `children` cost
  O(children) instead of scanning every entry: 600 k lookups over 620 k entries
  in 91 ms, and a miss in a flat 300 k-child directory in 876 µs. The drain
  loop now paces itself (`DRAIN_TIME_BUDGET`) and reports its lag instead of
  starving the rest of the daemon.
- **A silent daemon is an error.** A daemon that accepts a request and never
  answers now fails the client after 10 s with a message naming the instance,
  instead of hanging; `--socket` selects which daemon a command talks to.

### Added

- Fuzzy search gained a visible edit-distance budget (`-`/`+`) and the foldout
  band that opens it, so the cost of a wider match is a deliberate choice
  rather than a flag remembered from the last session.
- Platform pages, screenshots, and an installer whose packaging steps are
  checked by `scripts/verify-release-workflow.py` — the workflow's own `run:`
  bodies, replayed outside Actions.
